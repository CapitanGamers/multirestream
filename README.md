# MultiRestream

سرور + کلاینت C++ برای ویندوز، تقریباً همون کاری که Restream می‌کنه: یک استریم می‌گیری، بدون ری‌اینکود هم‌زمان به چند پلتفرم می‌فرستی، ویوی هر کدوم رو جدا می‌بینی، و چت‌هاشون رو تو یک نوار واحد مخلوط می‌کنی.

این یک محصول تجاری نیست؛ یک لایه‌ی کاربردیه روی FFmpeg. پخش واقعی (کپی بیت‌استریم، بدون اینکود دوباره) کار FFmpegه، رابط‌ها Win32 خالصن و هیچ وابستگی سوم‌شخصی ندارن.

```
کروم (لاگین توییچ/کیک/یوتیوب)     فقط روی PC تو
        │  CDP پورت 9333
        ▼
 mr_client.exe ── عنوان لایو رو از همین سیستم اعمال می‌کنه
        │         کلیدهای مقصد رو استخراج می‌کنه
        │  TCP :7788   (کلید استریم مقصد + عنوان، نه کل کوکی‌جار)
        ▼
 mr_server.exe روی VPS ── FFmpeg fan-out
        ▲
        │  RTMP :1935  کلید اینجست رو کلاینت از سرور می‌گیره
 OBS ───┘  یا دکمه «بده به OBS» از WebSocket 4455
```

## چی کار می‌کنه، چی نه

کار می‌کنه: اینجست RTMP + فن‌اوت هم‌زمان بدون ترنسکود (`-c copy -f tee`)، جداسازی خطای هر مقصد به‌طور جداگونه (`onfail=ignore`)، UI سبک سرور، UI کلاینت با کارت ویو و چت مخلوط و لوگوی پلتفرم، چت زنده‌ی توییچ روی IRC، و شمارنده‌ی ویو هر سه پلتفرم (اگه توکن/کلید درست باشه). چت یوتیوب هم هست ولی با پولینگ ساده - ناقصه، ولی پیام رد و بدل می‌شه.

کار نمی‌کنه: OAuth کامل، ریپلای و مدریشن چت، تغییر رسمی عنوان استریم (فقط یه راه‌حل نیمه‌کاره از طریق کروم هست، پایین‌تر توضیح دادم)، و چت زنده‌ی کیک (فقط اسکلت API ویو پیاده شده - چت روی Pusherه). سرور RTMP هم از صفر نوشته نشده؛ اون رو FFmpeg انجام می‌ده.

نوشتن یک سرور RTMP پایدار + همه‌ی APIهای چت پلتفرم‌ها از صفر، کار چند ماهه‌ست. این پروژه همون لایه‌ایه که روی VPS می‌ذاری و کنار OBS استفاده می‌کنی.

## پیش‌نیاز

روی VPS ویندوز و روی سیستم خودت:

1. Visual Studio 2019 یا 2022، با workload «Desktop development with C++»
2. CMake 3.16 یا بالاتر
3. [FFmpeg full build](https://www.gyan.dev/ffmpeg/builds/) - باید `ffmpeg.exe` تو `PATH` باشه یا مسیرش رو تو `config.json` → `ffmpeg_path` بذاری. بیلد باید TLS داشته باشه، برای RTMPS کیک و فیسبوک لازمه.

## ساخت

```
scripts\build-msvc.bat
```

خروجی: `build\Release\mr_server.exe` (برای VPS) و `build\Release\mr_client.exe` (برای سیستم استریمر).

## سرور روی VPS

1. `mr_server.exe` رو کنار `config.example.json` کپی کن.
2. بار اول که اجرا بشه `config.json` می‌سازه؛ این‌ها رو پر کن:

```json
"ingest_key": "یک_رمز_قوی",
"auth_token": "توکن_داشبورد",
"rtmp_url": "rtmp://live.twitch.tv/app/STREAM_KEY"
```

3. تو فایروال ویندوز و پنل دیتاسنتر فقط دو پورت رو باز کن: **1935** (از IP سیستم استریمر، برای OBS) و **7788** (از IP سیستم داشبورد). بقیه بسته بمونه.
4. سرور رو اجرا کن، بزن «شروع»، آدرس اینجست رو کپی کن. اگه OBS روی خود VPSه، آدرس می‌شه `rtmp://127.0.0.1:1935/live/INGEST_KEY`

## OBS

Settings → Stream:
- Service: Custom
- Server: `rtmp://IP_VPS:1935/live`
- Stream Key: همون `ingest_key`

خروجی رو H.264 + AAC بذار - چون سرور `-c copy` می‌کنه، همه‌ی مقصدها باید همین کدک رو قبول کنن (توییچ/یوتیوب/کیک معمولاً قبول می‌کنن). برای یوتیوب کی‌فریم هر ۲ ثانیه توصیه می‌شه.

پهنای باند VPS باید حداقل (مجموع بیت‌ریت × تعداد مقصد) + ۲۰٪ باشه. سه مقصد ۶ مگابیتی یعنی حدود ۲۲ مگابیت آپلود پایدار.

## کلاینت

`mr_client.exe` رو اجرا کن، آی‌پی VPS، پورت `7788` و توکن داشبورد رو بده، وصل شو.

کارت بالای صفحه ویوی هر پلتفرمه، نوار پایین چت مخلوطه. دایره‌ی رنگی کنار هر پیام لوگوی پلتفرمه: TW بنفش = توییچ، YT قرمز = یوتیوب، KK سبز = کیک، FB آبی = فیسبوک.

دسترس‌پذیری: کنترل‌های نیتیو Win32 با Narrator خونده می‌شن، هر پیام چت متن کامل «پلتفرم کاربر: پیام» رو نگه می‌داره، Tab بین کنترل‌ها حرکت می‌کنه، `Ctrl +` / `Ctrl -` سایز فونت رو از ۱۲ تا ۲۸ عوض می‌کنه، یک دکمه برای کنتراست بالا هست، `F11` تمام‌صفحه می‌کنه، فونت Segoe UI (فارسی و انگلیسی) و پنجره زیر ۹۰۰ پیکسل عرض نمی‌شه که کارت‌ها له نشن.

## توکن و API هر پلتفرم

**توییچ** - Stream key از داشبورد خودشه. برای گرفتن ویو یک اپ تو [dev.twitch.tv](https://dev.twitch.tv) بساز و `client_id` بذار؛ با App Access Token یا User Token و هدر `Authorization: Bearer`. چت بدون توکن هم با نیک `justinfan` قابل خوندنه (فقط خواندن)؛ برای چت لاگین‌شده `oauth_token` با اسکوپ `chat:read` لازمه. اینجست معمولاً `rtmp://live.twitch.tv/app/<key>` یا نزدیک‌ترین مورد از [ingest.twitch.tv/ingests](https://ingest.twitch.tv/ingests).

**یوتیوب** - Stream key از YouTube Studio → Go Live. اینجست: `rtmp://a.rtmp.youtube.com/live2/<key>`. برای ویو و چت یک `api_key` از Google Cloud (YouTube Data API v3) لازمه؛ فیلد `channel` رو Video ID لایو جاری بذار، نه نام کانال - این محدودیت خود APIه.

**کیک** - RTMPS، کلید از داشبورد کیک. اینجست معمولاً چیزی شبیه `rtmps://…global-contribute.live-video.net/app/<key>`. ویو از `api.kick.com` می‌آد؛ چت زنده روی Pusherه و تو این نسخه پیاده نشده.

## چند نکته‌ی عملی درباره‌ی VPS

- CPU برای `-c copy` تقریباً صفره - گلوگاه شبکه‌ست، نه پردازنده.
- اگه یک مقصد قطع بشه، `onfail=ignore` بقیه رو زنده نگه می‌داره؛ ولی tee یک پروسه‌ست - اگه خود FFmpeg بمیره، سرور ۲ ثانیه بعد ری‌استارتش می‌کنه.
- برای ایزوله‌ی قوی‌تر می‌شه هر مقصد رو یک پروسه‌ی FFmpeg جدا کرد - جاش تو `RestreamEngine` هست.
- RTMP روی ۱۹۳۵ رمزنگاری نداره؛ اگه OBS از اینترنت وصل می‌شه، یک تونل WireGuard/OpenVPN بین خونه و VPS بهتر از RTMP لخته.
- کلید استریم رو کامل تو لاگ چاپ نکن. الان فقط آدرس اینجست تو UI دیده می‌شه؛ کلید مقصد رو تو `config.json` نگه دار و دسترسی فایل رو محدود کن.

## ساختار کد

```
shared/     پروتکل، کانفیگ، Win32 helpers
server/     FFmpeg supervisor + ChatHub + TCP control + UI سبک
client/     داشبورد دسترس‌پذیر
```

پروتکل کنترل یک شیء JSON در هر خط، روی TCPه:

```json
{"type":"auth","token":"..."}
{"type":"get_state"}
{"type":"chat","platform":"twitch","user":"ali","text":"سلام"}
{"type":"viewers","platform":"youtube","viewers":120,"live":true}
```

## چرا C++ خالص، نه nginx-rtmp؟

چون خواستم سرور و کلاینت C/C++ باشن. هسته‌ی رسانه رو دادم دست FFmpeg چون نوشتن RTMP handshake + chunk stream + FLV mux پایدار، خودش چند هزار خط کد و منبع باگه. UI، کنترل، چت و سوپروایزر همه دست‌نوشته‌ی خودمه؛ بعداً هم می‌شه EasyRTMP یا MediaMTX رو جای FFmpeg لیسنر گذاشت بدون این‌که کلاینت عوض بشه.

## گردش‌کار جدید: کروم + عنوان + OBS

کوکی‌های کروم روی سیستم خودت می‌مونن، کل نشست کروم به VPS فرستاده نمی‌شه. چیزی که می‌ره فقط آدرس RTMP مقصد (استریم‌کی همون پلتفرم) و در صورت وجود، توکن توییچ برای چت سروره.

1. **سرور** - تو `config.json` فیلد `public_host` رو IP عمومی VPS بذار؛ کلاینت همینو به‌عنوان سرور OBS می‌گیره.
2. **کروم رو با دیباگ محلی باز کن** - همه‌ی پنجره‌های کروم رو ببند، بعد `scripts\start-chrome-debug.bat` رو اجرا کن. این کروم رو با `--remote-debugging-port=9333` روی `127.0.0.1` باز می‌کنه - پورت به اینترنت وصل نیست. اگه کروم قبلش باز مونده باشه، ویندوز پروفایل رو قفل می‌کنه و اسکریپت شکست می‌خوره.
3. **کلاینت** - به VPS وصل شو تا فیلد «اینجست OBS» پر بشه (`rtmp://VPS:1935/live/KEY`). بزن «خواندن کروم» تا توییچ/کیک/یوتیوب از روی کوکی تشخیص داده بشن. اگه کلید استریم از API اومد، «بفرست سرور» رو بزن. اگه نیومد (معمولاً برای یوتیوب و گاهی توییچ)، کلید رو دستی تو `config.json` سرور بذار. عنوان رو بنویس و «اعمال عنوان» بزن - توییچ و کیک از همین سیستم اعمال می‌شن، یوتیوب Studio هنوز OAuth رسمی می‌خواد. آخر سر پسورد WebSocket اوبیس رو بده (Tools → WebSocket Server Settings، پورت 4455) و «بده به OBS» رو بزن؛ کلاینت سرور و کلید اینجست رو ست می‌کنه و استریم رو Start می‌کنه.

**محدودیت واقعی نشست کروم:** توکن داخل کوکی توییچ (`auth-token`) توکن وب‌سایته، نه اپ Helix با اسکوپ `channel:manage:broadcast` - بعضی وقت‌ها عنوان با GQL وب می‌شینه، بعضی وقت‌ها نه. کلید استریم توییچ و کیک همیشه از API وب درنمی‌آد؛ مسیر پشتیبان پیست دستی تو کانفیگ سرورِ. یوتیوب Data API بدون OAuth اپ گوگل عنوان رو عوض نمی‌کنه - صرف لاگین کروم کافی نیست. و اگه VPS مال خودت نیست، `auth-token` توییچ رو نفرست سمت سرور؛ مقصد رو دستی تو کانفیگ بذار.
