# MultiRestream

سرور + کلاینت C++ برای ویندوز، شبیه ایدهٔ Restream:
یک استریم را می‌گیری و همزمان به چند پلتفرم می‌فرستی، ویو هر پلتفرم را جدا نشان می‌دهی، و چت‌ها را در یک نوار واحد مخلوط می‌کنی.

این یک محصول تجاری کامل نیست. هستهٔ واقعی پخش را FFmpeg انجام می‌دهد (کپی بیت‌استریم، بدون اینکود دوباره). رابط‌ها Win32 خالص‌اند؛ وابستگی سوم‌شخص ندارند.

```
کروم (لاگین توییچ/کیک/یوتیوب)     فقط روی PC تو
        │  CDP پورت 9333
        ▼
 mr_client.exe ── عنوان لایو را از همین سیستم اعمال می‌کند
        │         کلیدهای مقصد را استخراج می‌کند
        │  TCP :7788   (کلید استریم مقصد + عنوان، نه کل کوکی‌جار)
        ▼
 mr_server.exe روی VPS ── FFmpeg fan-out
        ▲
        │  RTMP :1935  کلید اینجست را کلاینت از سرور می‌گیرد
 OBS ───┘  یا دکمه «بده به OBS» از WebSocket 4455
```

## چه چیزی واقعاً کار می‌کند

| بخش | وضعیت |
|---|---|
| اینجست RTMP و فَن‌اوت همزمان بدون ترنسکود | بله، با FFmpeg `-c copy -f tee` |
| جداسازی خطای مقصد (`onfail=ignore`) | بله |
| UI سبک سرور (شروع/توقف، لیست مقصد، لاگ) | بله |
| UI کلاینت با کارت ویو و چت مخلوط + لوگوی پلتفرم | بله |
| چت زندهٔ توییچ (IRC) | بله |
| شمارندهٔ ویو توییچ / یوتیوب / کیک | بله، اگر توکن/کلید درست باشد |
| چت یوتیوب | پولینگ ساده (کامل نیست، ولی پیام می‌آید) |
| چت کیک | اسکلت API ویو؛ چت زندهٔ سوکت جدا نیاز دارد |
| OAuth کامل، ریپلای چت، مدریشن، عنوان استریم | نه — باید خودت اضافه کنی |
| سرور RTMP از صفر داخل C++ | نه؛ FFmpeg لیسنر است |

نوشتن یک سرور RTMP پایدار + همهٔ APIهای چت پلتفرم‌ها از صفر، کار چند ماهه است. این پروژه همان لایه‌ای است که روی VPS می‌گذاری و با OBS استفاده می‌کنی.

## پیش‌نیاز

روی **VPS ویندوز** و روی **سیستم خودت**:

1. Visual Studio 2019 یا 2022 با workload «Desktop development with C++»
2. CMake ۳.۱۶+
3. [FFmpeg full build](https://www.gyan.dev/ffmpeg/builds/) — فایل `ffmpeg.exe` باید در `PATH` باشد یا مسیرش در `config.json` → `ffmpeg_path` باشد. بیلد باید TLS داشته باشد (برای RTMPS کیک و فیسبوک).

## ساخت

```bat
scripts\build-msvc.bat
```

خروجی:

- `build\Release\mr_server.exe`  → روی VPS
- `build\Release\mr_client.exe`  → روی سیستم استریمر

## راه‌اندازی سرور روی VPS

1. `mr_server.exe` را کنار `config.example.json` کپی کن.
2. بار اول که اجرا شود `config.json` می‌سازد. آن را ویرایش کن:

```json
"ingest_key": "یک_رمز_قوی",
"auth_token": "توکن_داشبورد",
"rtmp_url": "rtmp://live.twitch.tv/app/STREAM_KEY"
```

3. فایروال ویندوز و پنل دیتاسنتر:
   - **1935 TCP** از IP سیستم استریمر (OBS)
   - **7788 TCP** از IP سیستم داشبورد
   - بقیه پورت‌ها را باز نگذار
4. سرور را اجرا کن → «شروع» → آدرس اینجست را کپی کن.

اگر OBS روی خود VPS است، آدرس می‌شود:
`rtmp://127.0.0.1:1935/live/INGEST_KEY`

## OBS

Settings → Stream:

- Service: **Custom**
- Server: `rtmp://IP_VPS:1935/live`
- Stream Key: همان `ingest_key`

خروجی را H.264 + AAC بگذار. چون سرور `-c copy` می‌کند، همهٔ مقصدها باید همین کدک را قبول کنند (توییچ، یوتیوب، کیک معمولاً قبول می‌کنند). کی‌فریم هر ۲ ثانیه برای یوتیوب توصیه می‌شود.

پهنای باند VPS باید **حداقل مجموع بیت‌ریت × تعداد مقصد + ۲۰٪** باشد. سه مقصد ۶ مگابیتی یعنی حدود ۲۲ مگابیت آپلود پایدار.

## کلاینت

1. `mr_client.exe` را روی سیستم خودت اجرا کن.
2. آی‌پی VPS، پورت `7788`، توکن داشبورد.
3. اتصال.

کارت بالای صفحه ویو هر پلتفرم است. نوار پایین چت مخلوط است؛ دایرهٔ رنگی کنار هر پیام لوگوی پلتفرم است:

- بنفش TW = توییچ
- قرمز YT = یوتیوب
- سبز KK = کیک
- آبی FB = فیسبوک

### دسترس‌پذیری کلاینت

- کنترل‌های نیتیو Win32 (دکمه، ادیت، لیست) — با Narrator خوانده می‌شوند
- هر آیتم چت متن کامل «پلتفرم کاربر: پیام» را نگه می‌دارد
- A+ / A− یا Ctrl + / Ctrl − اندازهٔ فونت ۱۲ تا ۲۸
- دکمهٔ ◐ کنتراست
- F11 تمام‌صفحه
- Tab برای حرکت بین کنترل‌ها
- حداقل عرض پنجره ۹۰۰px تا کارت‌ها له نشوند
- فونت Segoe UI (فارسی و انگلیسی)

## توکن‌ها و API

### توییچ

- Stream key از داشبورد توییچ
- برای ویو: اپ در [dev.twitch.tv](https://dev.twitch.tv) بساز، `client_id` بگذار
- App Access Token یا User Token با هدر `Authorization: Bearer`
- چت بدون توکن هم با nick `justinfan` خوانده می‌شود (فقط خواندن)
- برای چت لاگین‌شده: `oauth_token` با اسکوپ `chat:read`

آدرس اینجست توییچ معمولاً:
`rtmp://live.twitch.tv/app/<key>`
یا نزدیک‌ترین اینجست از [ingest.twitch.tv/ingests](https://ingest.twitch.tv/ingests)

### یوتیوب

- Stream key از YouTube Studio → Go Live
- اینجست: `rtmp://a.rtmp.youtube.com/live2/<key>`
- ویو و چت: `api_key` از Google Cloud (YouTube Data API v3)
- فیلد `channel` را **Video ID لایو جاری** بگذار، نه نام کانال. این محدودیت API یوتیوب است.

### کیک

- RTMPS. کلید را از داشبورد کیک بردار.
- اینجست رسمی معمولاً شبیه
  `rtmps://…global-contribute.live-video.net/app/<key>`
- ویو از `api.kick.com`. چت زندهٔ کیک روی Pusher است و در این نسخه پیاده نشده.

## نکات عملی VPS

- CPU برای `-c copy` تقریباً صفر است. گلوگاه شبکه است، نه پردازنده.
- اگر یک مقصد قطع شود، `onfail=ignore` بقیه را زنده نگه می‌دارد. با این حال tee یک‌پروسه است؛ اگر خود FFmpeg بمیرد سرور ۲ ثانیه بعد ری‌استارت می‌کند.
- برای ایزولهٔ قوی‌تر بعداً می‌توان هر مقصد را یک پروسهٔ FFmpeg جدا کرد (در `RestreamEngine` جا دارد).
- RTMP روی ۱۹۳۵ رمزنگاری ندارد. اگر OBS از اینترنت می‌آید، تونل WireGuard/OpenVPN بین خانه و VPS بهتر از RTMP لخت است.
- کلید استریم را در لاگ کامل چاپ نکن؛ الان URL اینجست در UI هست، کلید مقصد را در `config.json` نگه دار و فایل را محدود کن.

## ساختار کد

```
shared/     پروتکل، کانفیگ، Win32 helpers
server/     FFmpeg supervisor + ChatHub + TCP control + UI سبک
client/     داشبورد دسترس‌پذیر
```

پروتکل کنترل: یک شیء JSON در هر خط، TCP.

```json
{"type":"auth","token":"..."}
{"type":"get_state"}
{"type":"chat","platform":"twitch","user":"ali","text":"سلام"}
{"type":"viewers","platform":"youtube","viewers":120,"live":true}
```

## چرا C++ خالص، نه nginx-rtmp؟

خواستی سرور و کلاینت C/C++. هستهٔ رسانه را FFmpeg گذاشتم چون نوشتن RTMP handshake + chunk stream + FLV mux پایدار، چند هزار خط و منبع باگ است. UI و کنترل و چت و سوپروایزر همه C++ خودت است و می‌توانی بعداً EasyRTMP یا MediaMTX را جای FFmpeg لیسنر بگذاری بدون عوض کردن کلاینت.

## گردش کار جدید: کروم + عنوان + OBS

کوکی‌های کروم **روی سیستم خودت می‌مانند**. به VPS کل نشست کروم فرستاده نمی‌شود. چیزی که می‌رود: آدرس RTMP مقصد (همان استریم‌کی پلتفرم) و در صورت وجود توکن توییچ برای چت سرور.

### ۱) سرور

در `config.json` فیلد `public_host` را IP عمومی VPS بگذار. کلاینت همین را به‌عنوان سرور OBS می‌گیرد.

### ۲) کروم را با دیباگ محلی باز کن

همه پنجره‌های کروم را ببند، بعد:

```
scripts\start-chrome-debug.bat
```

این کروم را با `--remote-debugging-port=9333` روی **127.0.0.1** باز می‌کند. پورت به اینترنت و VPS وصل نیست.

اگر کروم باز بماند، ویندوز پروفایل را قفل می‌کند و اسکریپت شکست می‌خورد.

### ۳) کلاینت

1. به VPS وصل شو → فیلد «اینجست OBS» پر می‌شود (`rtmp://VPS:1935/live/KEY`).
2. «خواندن کروم» → توییچ / کیک / یوتیوب از کوکی تشخیص داده می‌شوند.
3. اگر کلید استریم از API آمد، «بفرست سرور» را بزن تا VPS مقصدها را ذخیره کند.
4. اگر کلید نیامد (معمول برای یوتیوب و گاهی توییچ)، کلید را از داشبورد پلتفرم در `config.json` سرور بگذار.
5. عنوان را بنویس → «اعمال عنوان». توییچ و کیک از همین سیستم زده می‌شوند. یوتیوب Studio هنوز OAuth رسمی می‌خواهد.
6. پسورد WebSocket اوبیس را بگذار (Tools → WebSocket Server Settings، پورت ۴۴۵۵) → «بده به OBS». کلاینت سرور/کلید اینجست را ست می‌کند و استریم را Start می‌کند.

### محدودیت واقعی نشست کروم

- توکن داخل کوکی توییچ (`auth-token`) توکن وب‌سایت است، نه اپ Helix با اسکوپ `channel:manage:broadcast`. عنوان گاهی با GQL وب می‌نشیند، گاهی نه.
- کلید استریم توییچ و کیک همیشه از API وب درنمی‌آید. مسیر پشتیبان: پیست دستی در کانفیگ سرور.
- یوتیوب Data API بدون OAuth اپ گوگل عنوان را عوض نمی‌کند. لاگین کروم کافی نیست.
- فرستادن `auth-token` توییچ به VPS فقط برای چت/ویو سرور است. اگر VPS مال خودت نیست، «بفرست سرور» را نزن و مقصد را دستی در کانفیگ بگذار.
